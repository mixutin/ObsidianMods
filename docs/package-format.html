OBSIDIAN PACKAGE FORMAT

Ship the build.
Keep your source.

Obsidian packages contain runtime files and metadata. A mod author does not need to publish implementation source.

Package layout

Native Obsidian plugins use the smallest package shape:

my-native-mod-1.0.0.zip
├── obsidian-mod.json
└── MyNativeMod.dll

PAK/IoStore and UE4SS packages are also supported. The manager detects their runtime files and places them in the correct game directories.

The manager verifies the catalog SHA-256 before extraction. Catalog builds must be hosted as GitHub Release assets in mixutin/ObsidianMods-Builds.

Manifest

{
  "schema": 1,
  "id": "my-mod",
  "name": "My Mod",
  "version": "1.0.0",
  "author": "Author",
  "loader": "obsidian-native",
  "game": "minecraft-dungeons-2",
  "game_builds": ["25041023"],
  "dependencies": [],
  "conflicts": []
}

Binary-only policy

Public mod archives should contain only files required to run the mod: compiled DLLs, Lua bytecode, PAK/IoStore containers, metadata and required third-party license notices. Source may stay in a private repository.

Catalog status

Every release can be marked stable, experimental or temporarily blocked. Blocked builds remain visible for transparency, but one-click installation is disabled until compatibility is restored.
